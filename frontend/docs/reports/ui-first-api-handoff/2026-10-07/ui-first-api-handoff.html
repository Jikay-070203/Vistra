Giả định nghiệp vụ: frontend đã được chốt và duyệt deploy; backend chưa có API, chỉ có ý tưởng sản phẩm và khung database ban đầu. Bảng dưới đây là yêu cầu mới gửi team Backend để cung cấp đủ dữ liệu cho UI được duyệt.

Tên endpoint, tên trường và JSON là đề xuất hợp đồng, không phải danh sách API đang tồn tại. Số tiền, tỷ lệ, ngày, ID, mã tỉnh, ảnh và URL là ví dụ minh họa cấu trúc; không phải kết quả đo, dự báo hay thông tin đã xác minh ngoài đời.

57 API đề nghị triển khai và 5 API cần chốt thêm. API dùng chung chỉ liệt kê một lần. Các response lịch trình được viết đầy đủ tại từng dòng; không dùng “giống API trước”, dấu ba chấm hay trường dữ liệu chưa định nghĩa.

Đã đọc route/component JSX, các control hiển thị và riêng phần registry trường trực tiếp sinh bảng/form quản trị. Không đọc nội dung services, API clients, endpoint constants, controllers, backend hoặc tài liệu API cũ. Không sửa frontend implementation.

Cách đọc và giả định bàn giao

  1. Cột Input là mô tả request: path thay vào URL, query thành query string, chỉ nội dung body gửi làm JSON body. GET không gửi JSON body. Các object path/query/body không phải wrapper gửi nguyên khối.
  2. Tiền nghiệp vụ là số nguyên VND; ngày là YYYY-MM-DD; thời điểm có offset +07:00. Label trình bày do FE định dạng hoặc nhận rõ bằng trường label. Các trường string trong form quản trị generic giữ đúng kiểu mà UI đang sử dụng.
  3. Đề xuất xác thực bằng session cookie. Login/OAuth đặt cookie qua HTTP header; logout hủy phiên. Server lấy user/role từ session và kiểm tra quyền; không tin ID/vai trò người gửi tự khai.
  4. Các nút lưu/tạo/sửa/xóa được đặc tả theo giả định lưu trên máy chủ để dữ liệu có thể dùng lại và quản trị chia sẻ. Nhãn “demo/lưu cục bộ/áp dụng tạm” hiện tại mô tả giai đoạn FE trước BE; tài liệu không thay đổi các nhãn đó.
  5. Riêng thanh toán đang được UI ghi rõ “không thu phí thật”: chỉ đặc tả API đọc gói/hạn mức/hóa đơn mẫu. Không yêu cầu Backend tự tạo checkout, đặt phòng, đặt xe hoặc hoàn tiền.
  6. List trả pagination và toàn bộ trường cần cho card/table/modal. Summary/counts toàn bộ không thay đổi khi chuyển trang hoặc lọc. Mảng ví dụ của catalog/list có thể rút gọn; không phải giới hạn số bản ghi server trả. Gợi ý điểm đến phải có đủ 5 phần tử; overview đủ 12 tháng; hành trình ví dụ đủ 4 ngày.
  7. version/expectedVersion là đề xuất kiểm soát đồng bộ khi chat, kéo thứ tự và chỉnh form cùng sửa một hồ sơ. Khi dữ liệu đã đổi, trả 409 để FE tải lại; không ghi đè im lặng.
  8. Schema JSON phục vụ UI không bắt Backend sao chép schema database. Backend ánh xạ dữ liệu lưu trữ sang response đã thống nhất và giữ một nguồn dữ liệu cho từng nghiệp vụ.

Những điểm BA cần thống nhất trước khi khóa contract

  • Nhóm tuổi: UI ghi người lớn “từ 12 tuổi”, người cao tuổi “từ 60 tuổi”, nên nhãn đang chồng nhau. Đề xuất count là ba nhóm không trùng và tổng = adults + elderly + children; cần thống nhất cách nhập, không suy diễn đã được duyệt.
  • Nhịp độ: create-trip/profile và Planner có bộ nhãn khác nhau. Cần map chung hoặc giữ các code slow/balanced/fast/gentle/busy với paceLabel đúng control; không làm mất lựa chọn khi mở lại form.
  • Ngân sách: create-trip/destinations có khoảng 1 triệu–500 triệu, slider bước 500.000; số gõ trực tiếp không nhất thiết là bội số bước. Community dùng khoảng tới 1 tỷ. Cần giữ min/max và basis theo đúng trang.
  • Địa điểm: TỈNH DU LỊCH là nơi đến, không phải điểm xuất phát. Origin lấy từ hồ sơ. Mã tỉnh trong JSON chỉ là ví dụ; Backend phải cấp code/name từ danh mục thống nhất, không đoán từ chuỗi destination.
  • Chu kỳ gợi ý: Destinations dùng tháng dương lịch tiếp theo tại Asia/Ho_Chi_Minh. Traveler preset “3–4”, “5+” là nhóm; không hiểu 3 và 5 là số thành viên chính xác.
  • Vòng đời hành trình: đề xuất draft → confirmed bằng CTA xác nhận, rồi có thể published. Cần chốt việc sửa hồ sơ confirmed có quay về draft/gỡ publication hay không; chat không tự chốt.
  • Metrics: chốt định nghĩa active user, cửa sổ availability, doanh thu ước tính/đã ghi nhận, MRR, mẫu số chuyển đổi trả phí và nguồn benchmark. Các số mẫu không phải cam kết thuật toán hoặc kết quả đo.
